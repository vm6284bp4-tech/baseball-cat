## 1. 核心設定

| 項目 | 內容 |
|---|---|
| 遊戲名稱 | **棒球貓 BASEBALL CAT**（暫定；英文標題不含禁用詞，字元數與符號皆合規） |
| 畫風 | 美式 Q 版貓咪角色，成人向可愛吉祥物調性（非兒童角色、非幼體化視覺語言） |
| 題材 | 棒球比賽，投手 vs 打者 |

**原創風險檢查記錄**（討論過程結論，供之後複查）：
- 原始構想「套用愛麗絲夢遊仙境角色」風險高：① ID 217 無未成年/兒童形象——愛麗絲本體是兒童角色，即使改畫風仍可能被辨識；② ID 253 與既有遊戲近似——該題材已被多款上架 slot（White Rabbit Megaways、Wonderland、Wonky Wabbit、Mad Hatters 等）高度符號化使用，角色/美術/呈現容易疊到 ≥2 項近似。**已否決。**
- 改用「Q 版貓咪」＋原創名稱「棒球貓」後：風險大幅降低，貓是通用吉祥物題材、名稱不含任何現實品牌/聯盟聯想（原本「棒球大聯盟」有暗示 MLB 品牌的風險，已排除）。**建議上線前仍花時間搜尋是否已有「貓＋棒球」組合的既有遊戲，排除 ID 253 風險。**
- 執行上要避免：真實 MLB 球隊 Logo/配色/制服設計（商標風險，與 Stake 自己的規則無關，但仍是法律風險）；過度幼體化的視覺語言（嬰兒化大眼、奶瓶色系等，會貼近「吸引未成年」）。

## 2. 玩法骨架

| 項目 | 內容 |
|---|---|
| 盤面 | **5×5 Ways**（固定輪帶，非 Megaways 式隨機列高，不涉及該專利機制），5⁵ = **3,125 ways** |
| Bet Mode | 兩個模式，**皆 1.0× 成本**，玩家用 UI 按鈕隨時免費切換（對應 `/wallet/play` 的 `mode` 參數），**預設進入投手模式** |
| 投手模式 `pitcher` | 一般玩法 + 特色投手，**低波動** |
| 打手模式 `batter` | 一般玩法 + 特色打手，**高波動** |
| 美術共用範圍 | UI 外殼（下注面板、按鈕、設定、規則頁框架）共用；**背景與部分符號**依模式切換而不同（哪些符號共用/替換，待第 5 節決定） |

> 兩個模式各自獨立算 RTP，須各自落在 96.0–96.7%；兩者皆為 1.0× 成本，需各自滿足「1.0× 模式標準差 ≥ 0.6」的下限（低波動的投手模式也不能壓到接近無波動）。

## 3. 特色機制（兩模式共用引擎，參數方向相反）

### 3.1 觸發

| Scatter 數 | 保底額度 | 投手模式技能 | 打手模式技能 |
|---|---|---|---|
| 3 | 0 | — | — |
| 4 | 1 | 分身球 | 預測球路 |
| 5 | 2（累加） | +高速球 | +多重打擊 |

- Scatter 符號本身可能依模式有不同造型，但觸發邏輯共用（3/4/5 門檻一致）。
- 保底額度＝「本輪對決中，保證有 N 次對決直接判定成功」的名額，**不是**碰到快輸才跳出來的補救，是先把總結果決定好之後，其中固定佔掉 N 個成功名額（技能用掉即扣除）。

### 3.2 對決流程

| | 投手特色 | 打手特色 |
|---|---|---|
| 對手數 | 3 位打者，依序對戰 | 3 位投手，依序對戰 |
| 單次對決門檻 | **3 球全中**（每球皆成功）才算過關這位對手；未被救回的「被打中」＝整輪立即結束（失敗退場） | **3 球內任1命中**即過關這位對手，命中後不需打完剩餘球數，直接進下一位 |
| 全通關 | 3 位對手全過 → 大獎（通關加成，見 3.3） | 同左 |

每一球的判定順序：
1. 若還有未用的保底額度 → **直接判定本球成功**，扣 1 額度
2. 若無保底額度 → 從該模式的基礎權重表隨機抽「成功／失敗」

成功結果會隨機挑一種演出變體播放（**純演出，不影響分數**）：
- 投手：乾淨三振 / 接殺式三振（即「救命機制」：打中但被接殺，結果仍算成功）
- 打手：乾淨命中 / 驚險命中（原本看似落空，最後一刻擦中）

失敗結果同理也可有對應的戲劇化演出變體（例如投手「看似三振卻在最後一刻被打中」），純粹增加重複遊玩的新鮮感，不影響任何機率或分數。

### 3.3 計分（階梯式，兩模式陡度相反）

| 對手位置 | 投手模式（平緩階梯，支撐低波動） | 打手模式（陡峭階梯，支撐高波動） |
|---|---|---|
| 第1位 | 低 | 低 |
| 第2位 | 中（差距小） | 中（差距大） |
| 第3位 | 高（差距小） | 高（差距大） |
| 全通關加成 | 額外倍率加成，**幅度小** | 額外倍率加成，**幅度大** |

- 保底額度強制成功時，該球拿到的分數＝**當下卡在第幾位對手的階梯分數**（不是獨立固定值）。
- 實際數值（低/中/高各多少、通關加成倍率、觸發機率權重）全部待定，由數學階段的模擬＋Rust 優化器調出來，目標是兩模式各自卡進 96.0–96.7% RTP，同時讓打手的標準差明顯高於投手（兩者皆需 ≥0.6 下限）。
- 設計筆記：投手「3 球全中才過關」的結構天生偏向高波動（容易早死、少數全通關但分數集中），打手「1 中即過關」天生偏向低波動（容易穩定過關）——階梯陡度與通關加成的方向刻意與此結構相反，用來抵消結構性傾向，實際是否能精準落在目標波動差異，要等模擬驗證。
