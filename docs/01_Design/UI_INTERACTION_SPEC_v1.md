# 棒球貓 BASEBALL CAT — 介面／互動規格書 v1（前端開發用）

> 2026-11-19 · 企劃撰寫。**目的：前端開發不用再自己判斷「畫面該長什麼樣、按鈕該怎麼互動」，照這份文件的區塊配置、狀態機、互動對應表去實作即可。** 遊戲機制（規則、數值）以 [GDD_BASEBALL_CAT_v0.1.md](GDD_BASEBALL_CAT_v0.1.md) 為準，這份文件不重複機制敘述，只定義「機制結果要怎麼被看見、怎麼被操作」。
>
> 美術資產一律用佔位圖形（純色/漸層色塊、PixiJS Graphics 畫的圖案），這份文件規定的是**版面結構、狀態切換、互動行為**，不是最終美術——但版面結構、動畫節奏、資訊階層是確定要求，不是前端可以自由決定的範圍。

---

## 0. 總覽：這是一台老虎機，不是一個網頁表單

最常見的錯誤：把下注面板、模式切換做成網頁常見的「標題＋滿版按鈕＋表單」排版。**老虎機的畫面結構是：轉輪／特色畫面佔滿視覺主體，所有操作收斂在底部一條 HUD 列**。整個畫面應該是一個深色、連貫的「機台」構圖，不是一疊獨立的卡片/表單區塊。

## 1. 畫面結構總覽（ASCII wireframe）

```
┌──────────────────────────────────────────────────────────┐
│  棒球貓 BASEBALL CAT              [🔊][⚙][ℹ]  ← Header(薄) │
├──────────────────────────────────────────────────────────┤
│         ⦗ 投手 Pitcher ⦘ ⦗ 打手 Batter ⦘   ← 模式切換(緊湊) │
│                                                            │
│  ┌────────────────────────────────────────────────────┐  │
│  │                                                      │  │
│  │              [ GAME STAGE：轉輪 / 特色畫面 ]          │  │ ← 主視覺區
│  │              （有實體外框，填滿大部分空間）             │  │   (填滿寬度，
│  │                                                      │  │    佔視覺主體)
│  │                                                      │  │
│  └────────────────────────────────────────────────────┘  │
│                                                            │
├──────────────────────────────────────────────────────────┤
│ 餘額      下注額        ⬤ SPIN ⬤       贏分      [⏭][▶自動] │ ← 底部HUD(固定)
│ 1000.00    1.00         (大圓鈕,置中)    +12.40                │
└──────────────────────────────────────────────────────────┘
  [▸ QA / Debug 面板]  ← 收合、低調、與上方遊戲畫面明顯區隔（分隔線+淡化樣式）
```

**分區比例（直式桌機 960×700 畫布內，約略）**：Header 5%／模式切換 8%／Game Stage 65%／底部HUD 15%／QA面板在畫布外或畫布下方另開摺疊區，不佔用遊戲畫面空間。Game Stage 必須是視覺上最大的連續區塊，**不可以出現大片純背景色的空白**——沒有內容時也要有外框/底板，讓它看起來「有東西在那裡」，而不是留白。

## 2. 各分區詳細規格

### 2.1 Header（薄）
- 左：遊戲名稱「棒球貓 BASEBALL CAT」，字級中等，不做成巨大標題。
- 右：三個小圖示按鈕（圓形或方形小按鈕，不是文字按鈕）：🔊 靜音切換／⚙ 設定（可先無功能，佔位）／ℹ 規則說明（可先無功能，佔位，之後要接規則頁）。
- 高度固定、不隨內容變化。

### 2.2 模式切換（緊湊）
- **不是**兩個等寬、佔滿畫面寬度、像分頁籤的按鈕。改成：置中、寬度自適應內容的「分段式切換鈕」（segmented control／pill toggle），兩個選項並排、中間無縫，整體寬度約畫面寬度的 1/3～1/2，不頂滿版。
- 每個選項內：小圖示（投手＝球/手套圖案，打手＝球棒圖案，用簡單幾何圖形畫即可）＋文字（「投手 Pitcher」／「打手 Batter」）。當前選中的那個要有明顯高亮（底色/邊框），未選中的要明顯淡化。
- 對局進行中（轉動中或特色進行中）這個控制要 disable（視覺上變灰），不能在對局途中切換模式。

### 2.3 Game Stage（主視覺區，狀態機見第3節）
- 永遠有一個可見的外框／底板（PixiJS `Graphics.roundRect`，深色半透明或對比色），即使內容是空的（極少見，理論上一直有內容）也要看得出「這是一個畫面」。
- 這個區域在「基礎遊戲」跟「特色/獎金遊戲」兩種狀態之間是**整個場景替換**（見 GDD 設計理由：特色是獨立階段，不是轉輪上疊加的東西），不是漸層淡出淡入也不用太講究轉場特效，但換場那一刻要讓玩家明確感覺到「進入了不同畫面」（例如底板顏色/邊框風格改變）。

### 2.4 底部 HUD（固定高度，由左到右）
1. **餘額 Balance**：小標籤 + 數值（例：「餘額 1000.00」）。
2. **下注額 Bet**：小標籤 + 目前金額 + 可調整（下拉或 +/- 都可以，但視覺上要緊湊，不要佔太寬）。
3. **SPIN 按鈕**：**全畫面視覺上最大、最顯眼的單一控制元件**，圓形，置中。轉動中這顆鈕要換成「進行中」狀態（例如變色/顯示簡單的忙碌指示），不可重複觸發。
4. **贏分顯示**：對局結束後在這裡顯示本局總贏分（倍數 + 金額），0 贏分時顯示淡化的「本局無贏分」而不是空白。
5. **功能圖示區**（最右側，小圖示鈕）：⏭ 快轉（跳過演出直接看結算，QA/玩家都可用）、▶ 自動玩（可先做成有確認步驟的佔位按鈕，不用真的實作自動連續下注邏輯）。

### 2.5 QA / Debug 面板
- 維持現有的收合面板（預設收起），但樣式要跟上面的遊戲UI明顯分開（例如用分隔線 + 偏灰/偏淡的配色，標示「開發者工具」），不能看起來像遊戲畫面的一部分。

## 3. 畫面狀態機（Game Stage 區域，逐狀態說明）

### 3.1 基礎遊戲 · 待機（Idle）
- 顯示 5×5 符號網格，填滿 Game Stage 的可用空間（網格本身也要有自己的底板/外框，跟 Game Stage 外框視覺上區隔出「這是轉輪」的實體感）。
- 無操作時維持上一輪結果（或遊戲剛載入時的初始亂數網格），不要顯示「按下 SPIN 開始」這種提示文字疊在網格上——網格本身存在就是待機狀態的視覺。

### 3.2 轉動中（Spinning）— 對應 `spin_result` 事件觸發時
見第6節「轉輪動畫規格」，這是本次重點修正項目，不可做成瞬間跳結果。

### 3.3 中獎呈現（Win Celebration）— 對應 `base_game_win` 事件
- 每個有中獎的符號用明顯高亮處理（邊框發光/加粗，顏色跟未中獎符號有明顯反差）。
- 畫面上（Game Stage 內，網格下方或疊加）顯示本次中獎的符號、連線數、倍數（例：「OPP1 x3 → 0.50x」），多個中獎並列顯示，不要只顯示加總後的數字（玩家要看得出「為什麼贏」）。
- 沒有中獎時這個區塊不顯示（或顯示淡化的「無中獎」），不要留下中獎文字的殘影。

### 3.4 Scatter 觸發轉場（Scatter Trigger）— 對應 `scatter_trigger` 事件
- Game Stage **整個換成特色對決場景**（見 3.5），換場時刻要有清楚的視覺提示：場景標題「獎金遊戲 Bonus Game — 投手模式/打手模式」置中顯示，下方立刻顯示本次觸發拿到的保底額度／生命值數量（圖示化，見第7節）。

### 3.5 特色對決（Duel）— 對應 `pitch` / `opponent_cleared` / `feature_end` 事件
見第7節「特色對決視覺規格」。

### 3.6 回合結算（Round Result）— 對應 `round_result` 事件
- 特色若有觸發，先顯示完 3.5 的 feature_end 結算面板，接著場景換回「基礎遊戲」網格（顯示剛剛那次轉動的最終網格，不是空白），同時在底部 HUD 的贏分欄位顯示最終總贏分。
- 若特色沒有觸發（純基礎遊戲回合），直接在網格中獎呈現後，於底部 HUD 顯示總贏分，不需要額外的全畫面結算卡。

## 4. 互動元件總表

| 元件 | 觸發動作 | 行為 |
|---|---|---|
| SPIN 按鈕 / 空白鍵 | 按下 | 若無進行中回合且餘額足夠 → 扣下注額 → 呼叫 `play()` → 進入轉動動畫 → 依序播放 events；進行中時忽略重複觸發 |
| 模式切換（投手/打手） | 點擊未選中的選項 | 若無進行中回合 → 切換 `mode`；進行中時整個控制 disable，點擊無效 |
| 下注額控制 | 調整數值 | 更新目前下注額，僅能選 `authenticate()` 回傳的 `betLevels` 其中之一 |
| 🔊 靜音鈕 | 點擊 | 切換靜音狀態（目前無音效，先做狀態切換的視覺即可，見 DEVLOG 既有做法） |
| ⏭ 快轉 | 點擊 | 呼叫既有的 `skipToEnd()`，跳過動畫直接顯示本回合最終結果 |
| ▶ 自動玩 | 點擊 | 先彈出確認步驟（哪怕是簡單的 confirm 對話），不要求真的實作連續下注迴圈 |
| ⚙ 設定／ℹ 規則說明 | 點擊 | 目前可以是無功能佔位（之後接規則頁/設定頁），但按鈕本身要存在且看起來可點擊 |
| QA/Debug 面板展開鈕 | 點擊 | 展開/收合既有的強制 scatter/seed/pitchOutcomes 控制項，行為不變 |

## 5. 符號視覺分級規範

所有符號格子統一用圓角卡片（`roundRect`），固定尺寸、固定格間距。依階級套用不同邊框/底色樣式，不是只換填色：

| 階級 | 符號 | 邊框/樣式規則 |
|---|---|---|
| Wild | WILD | 最粗的金色邊框 + 明顯不同的底色（例如深金/琥珀色底），單格/整軸兩型態都套用同一套邊框規則，差異只在整軸版本橫跨整條軸並加上投球/打擊姿勢的佔位圖形 |
| Scatter | SCATTER | 角落加一個星形或菱形徽章裝飾（純圖形，不需要文字），邊框用跟其他符號都不同的顏色（例如紅色或亮橘），讓它在畫面上一眼就能認出來 |
| 高階 | HIGH_OPP3 / HIGH_OPP2 / HIGH_OPP1 / HIGH_BAT | 銀色系邊框，底色統一但可依符號給予些微色調差異 |
| 低階 | LOW_JERSEY / LOW_GLOVE / LOW_BASE / LOW_CAP | 素面邊框（深灰/深綠），底色最樸素 |

中獎符號在上述樣式基礎上再疊加高亮效果（第 3.3 節）。

## 6. 轉輪動畫規格（本次最高優先修正項目）

**規則：`spin_result` 事件觸發時，5 條轉輪必須有看得見的捲動動畫，不可以瞬間跳成最終結果。**

- 用 PixiJS 內建的 `Ticker` 手動做位移補間（不需要額外動畫套件）：每條轉輪的符號欄位用一個可變的垂直偏移量繪製，從一個起始捲動位置動畫到 0（最終定位），過程中可以用快速輪替佔位符號製造「模糊捲動」的感覺。
- **交錯停輪**：第1軸先停，之後第2、3、4、5軸依序停下，每軸間隔約 120–150ms——這是老虎機最重要的視覺識別特徵，一定要做出來，不可以5軸同時停。
- 停輪時要有輕微的「超過一點再彈回」的緩動效果（overshoot and settle），不需要複雜的動畫曲線，簡單的 ease-out + 小幅回彈即可。
- 全部5軸從開始到完全停止，總時長抓 1～1.5 秒，不要拖到 5 秒以上，要有「俐落」的手感。
- 玩家按下 SPIN 到看到轉輪開始捲動之間，不應該有明顯延遲。

## 7. 特色對決視覺規格（獎金遊戲 Bonus Game）

### 7.1 整體排版：VS 式對戰構圖
- 畫面左右（或上下，依實作判斷哪個在畫布比例下更合適，但要有明確的「兩方對峙」感）分成「我方」與「對手」兩側，中間放一個簡單的 VS 標誌或箭頭圖案。
- 對手側：目前對戰中的那位對手用明顯的框（佔位的人形剪影色塊即可）標示，顯示「對手1/2/3」字樣；尚未對戰、已清掉、已淘汰的對手用不同的淡化/高亮處理區分狀態（待機=灰、進行中=黃/亮、已清掉=綠、淘汰=紅，沿用既有配色邏輯即可，但要用在這個新排版裡）。

### 7.2 保底額度／生命值：圖示化量表
- **不要只顯示文字**「生命值：2 剩餘」。改成一排小圖示（圓點/愛心/棒球圖案皆可，三選一統一風格），已用掉的畫成空心/淡化，剩餘的畫成實心/亮色。例如生命值上限2、剩餘1：● ○（一實一空）。
- 文字標籤可以保留在旁邊（例：「生命值」），但圖示量表是主要視覺，文字是輔助。

### 7.3 每球判定：打擊特效
- 對應 `pitch` 事件，除了現有的文字提示（成功/失敗/保底成功/失敗＋扣生命值），加上一個簡短的視覺衝擊效果：命中（success/forced_success）用亮色閃光或小幅放大再復原；失敗（failure/failure_life_used）用偏紅的閃爍或畫面小幅震動（offset 再彈回即可，不需要真的 camera shake 系統）。
- 效果要短（幾百毫秒內），不能拖慢整體節奏。

### 7.4 對手清關／結算：獎勵面板風格
- `opponent_cleared`：該對手的框變成清關狀態的同時，底分跟抽到的倍數要各自用獨立的小標籤/徽章顯示（例如兩個並排的圓角標籤：「+1.0 底分」「×1.5 倍數」），不要寫成一行文字。
- `feature_end`：用一個獨立的、有邊框裝飾的結算卡片（不是一段文字），裡面分行列出：結束原因（全通關/提早結束，中英文皆標示）、累積底分、每個抽到的倍數（逐一列出，不只顯示相乘後的結果）、最終倍數——層次要分明，玩家要能一眼看出「底分 × 倍數們 = 最終倍數」這個公式。
- `round_result`：底部 HUD 的贏分欄位更新即可（見 2.4），不需要再疊加一個全畫面彈窗，除非贏分特別大（但「特別大」的判斷標準這份文件不定義，先統一用 HUD 顯示）。

## 8. events → 畫面行為 對應表（逐一列出，避免遺漏）

事件格式定義見 `frontend/src/lib/mockRgs/index.js` 檔頭註解，欄位不在此重複，只列「收到這個事件要做什麼」：

| event.type | 畫面行為 |
|---|---|
| `spin_result` | 觸發第6節的轉輪捲動動畫，動畫結束後網格停在 `grid` 的最終內容；同時依 `wildCells` 套用 Wild 單格/整軸樣式 |
| `base_game_win` | 對應符號套用中獎高亮（3.3節），並列顯示中獎明細 |
| `scatter_trigger` | 整個 Game Stage 換場成特色對決場景（3.4節），顯示保底額度/生命值圖示量表初始值 |
| `pitch` | 更新對手狀態框（進行中）、觸發打擊特效（7.3節）、更新保底額度/生命值圖示量表、更新命中數（打手模式） |
| `opponent_cleared` | 該對手框轉為清關狀態，顯示底分+倍數標籤（7.4節） |
| `feature_end` | 顯示結算卡片（7.4節） |
| `round_result` | 更新底部 HUD 贏分欄位、場景換回基礎遊戲網格（3.6節） |

任何未列在上面、未來可能新增的事件類型，前端要維持現有的「記錄但不中斷播放」防呆處理（沿用既有 `roundPlayer.svelte.js` 的 `unhandledEvents` 機制），不可以讓未知事件類型讓整個播放卡住。

## 10. 給前端開發的實作注意事項
