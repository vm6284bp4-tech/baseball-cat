# 棒球貓 BASEBALL CAT

Stake Engine 平台 SLOT 遊戲企劃案。與另一款賽博龐克題材的專案 **ANKH PROTOCOL** 並行開發，**各自獨立版控、互不影響**（那款的程式碼/文件在另一個 repo）。

## 目前狀態（2026-11-18）

**階段：企劃階段，D1/D2/D4 已定案，D3 暫定、D5 待數學階段。** 玩法機制骨架、符號清單結構、最大贏分目標與遊戲名稱已定稿，正式數值尚未開始。

已定案（細節見 GDD 第 1–5 節）：
- 畫風：美式 Q 版貓咪，成人向吉祥物調性（否決過「愛麗絲夢遊仙境」方案，兒童角色＋既有遊戲近似風險過高）
- 盤面：5×5 Ways（固定輪帶，3,125 ways）
- 兩個 Bet Mode，皆 1.0× 成本，UI 按鈕隨時切換，預設投手模式：
  - **投手模式**（低波動）：3 球全中才過關一位打者
  - **打手模式**（高波動）：3 球內任1命中即過關一位投手
- 觸發：scatter 3/4/5 → 保底額度 0/1/2（分身球/高速球＝投手技能；預測球路/多重打擊＝打手技能）
- 計分：按對手位置（1/2/3）階梯式給分，投手平緩、打手陡峭；全通關加成倍率同理
- 符號：共 10 個（Wild／Scatter／高階4／低階4），高階含 3 隻對手貓＋球棒，Wild 為主角貓、依模式有單格/整軸兩型態，整軸擴展純演出不影響實際贏分；scatter 觸發的特色正式命名為「獎金遊戲 Bonus Game」（非傳統免費遊戲）
- 最大贏分目標：投手模式（低波動）3,000×／打手模式（高波動）15,000×，模式切換 UI 會直接顯示兩者最大倍數作為差異化賣點（暫定目標，待 D5 模擬微調）
- 遊戲名稱「棒球貓 BASEBALL CAT」已定案，重名搜尋未發現「貓＋棒球」組合的既有遊戲
- 計分機制 v2：取代舊版「階梯分數＋全通關加成」，改成每清一位對手累加該對手底分、並從該對手專屬倍數池抽一個倍數，結束時用「底分總和 × 所有已抽倍數相乘」算最終贏分（細節見 GDD 第4.3節）
- 已核對過 Stake 平台合規要點（標題、無狀態、ways 機制專利風險、原創近似風險）

待決定（見 GDD 第 6 節 D3、D5、D6）：
- D3 是否需要額外紅利層（暫定走簡單版，Wild 倍數/連消/獎金遊戲連勝加成留待 D5 模擬後再議）
- D5 底分/倍數池檔位/保底機率等正式數值（待模擬 + Rust 優化器產出）
- D6 保底額度對打手（任1中即過）與投手（全中才過）規則效果不對等（同樣5顆scatter，打手全通關機率≈72.5% vs 投手≈4.9%），已記錄待後續處理

## 快速上手（換電腦 clone 下來第一件事）

1. 讀 [docs/01_Design/GDD_BASEBALL_CAT_v0.1.md](docs/01_Design/GDD_BASEBALL_CAT_v0.1.md) — 完整企劃記錄，含每個決策的理由
2. 跑機制原型（純 Python 標準庫，不用裝任何套件）：
   ```bash
   python tools/baseball_cat_proto.py
   ```
   會印出投手/打手兩模式各自跑 20 萬輪的統計數字。**裡面所有機率/分數都是佔位值，不是正式 RTP**，純粹驗證「觸發分層→保底額度→對決規則→階梯分數→通關加成」這套邏輯跑不跑得通。
3. `shared_reference/` 是 Stake Engine 平台規則的參考副本（標題禁用詞、RTP 區間、審核檢查清單…），複製自主專案的 `shared/`，**不是正式來源**，只是讓這個 repo 單獨 clone 時不用再回頭找平台規則。

## 之後要做數學 SDK 實作時
