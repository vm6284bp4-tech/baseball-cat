# STAKE（Engine）平台上架指南 v0.2（PM）

> 2026-11-14 · **v0.2 已用官方 Studio 文件實際核對**（`stake-engine.com/docs`），取代 v0.1。
> ⚠️ **v0.1 有多項錯誤已更正**：平台現名 **Engine Studio**；RTP 規則不是「±0.5%」而是 **96.0–96.7% 固定區間**；新增「無狀態」「3 星評級」等硬性規則。
> 仍需登入 Studio 才看得到：審核檢查表詳細版（但公開的 `prompt.md` 已含完整條目編號，見 APPROVAL_CHECKLIST.md）。

## 1. 平台是什麼

**Engine Studio** 是 Stake 的第三方遊戲平台。你做「數學」＋「前端」，Engine 負責審核、託管（CDN + RGS）、發行、付款。通過審核的遊戲自動上架 **Stake.com / Stake.us / Stake.mx / Stake.eu**。任何國家任何人都可做，無 KYC。

## 2. 商務條件（已確認）

| 項目 | 內容 |
|---|---|
| **只上 Stake**（官方建議） | **Profit Share：10% GGR**；或 **Guaranteed：7.5% 預期 GGR** |
| Stake + 網路（其他營運商） | 各 5% / 3.75%；但 Stake 曝光變少、不能被推廣。**官方建議幾乎所有工作室選「只上 Stake」** |
| 公式 | GGR = 總投注 − 總派彩；預期 GGR = 總投注 × (1 − RTP) |
| Profit Share 風險 | 當月 GGR 為負 → 記為負餘額（債務）滾存，**不用倒貼**，之後賺回才領錢 |
| Guaranteed | 依預期值固定計算，沒有波動、沒有債務。官方建議新手選這個 |
| 切換 | 隨時可在 Payments 頁切換，首款遊戲上線後次月 1 日生效 |
| 發薪 | 每月 1 日，發上月（UTC）款項，USDT/USDC（ERC-20），金額 > $0 就發 |
| 只算「Real」投注 | 實況主/Stake 出資的 affiliate 玩家不計入分潤 |

> 發行方式**一旦提交就固定**，只上 Stake 的遊戲日後不能改上網路。

## 3. 技術架構

```
玩家瀏覽器 ──launch URL(sessionID, rgs_url, lang, currency, device, social)──▶ 靜態前端（Engine CDN）
   前端 ──/wallet/authenticate → /wallet/play → /wallet/end-round──▶ RGS
   RGS 依權重 CSV 抽一局 → 回傳該局 events → 前端只「播放」
```
- **全部結果預先算好**（books + 權重 CSV），RGS 不即時運算，前端不能影響輸贏。
- 金額為 6 位小數整數：`1_000_000` = 1.00。派彩倍率以「下注的百分之一」為單位的整數（`1150` = 11.5×），最多 2 位小數。

## 4. 硬性規則（全部已核對）

### 4.1 遊戲設計
| 規則 | 內容 |
|---|---|
| **無狀態 Stateless** | **每次下注獨立**；不能有累積獎池、Gamble（雙倍）、續玩、提早收錢（cash-out）。→ 我們的機制（免費遊戲內倍率累積）發生在「單一局的 book 內」，**合規**；但不能跨局保留任何東西 |
| 原創 | 不得已在他處上架／授權；不得與既有遊戲過度相似（標題、Logo、主角/符號、主題美術、核心機制、整體呈現 ≥2 項近似即不通過） |
| 品牌 | 不得含 Stake™/Kick™ 品牌或主題 |
| 未成年 | 不得吸引未成年；**含兒童或兒童風角色的藝術描繪也不行** |
| 標題禁用詞 | Megaways、XWays、Enhanced、Boosted、RTP、"Gates of…"、"…bonanza"、**Olympus**、Rush、Kraken、Waylanders，及任何暗示與其他發行商/系列有關的字詞。標題不可含 `& ' 重音符號` |
| 內容 | 不得冒犯、露骨、低俗 |
| AI 素材 | **允許**，但品質要與一般素材同級，且必須自己擁有商用權 |
| 上線後鎖定 | **不能改數學、不能加模式、不能改玩法機制**；前端只能小修（bug、效能、新語言、小幅視覺） |
| 遊戲名稱 | 上線後不可改 |

### 4.2 數學（Math verification）
| 檢查 | 要求 |
|---|---|
| **RTP** | **每一個模式都必須介於 96.0%–96.7%**（模式之間不必相同）。**我們目標 96.30%，保留 ±0.3% 安全邊際** |
| 最便宜模式 | 成本必須 = 1.0× |
| 波動度 | 1.0× 模式標準差 ≥ 0.6 |
| 最大贏分 | 任何模式 ≤ 1,000,000×（硬性）；且「應合理可達」，通常比 1/10,000,000 更常見 |
| 模式成本 | ≤ 50,000×（硬性）；> 5,000× 會被降低下注額度 |
| 模式數 | ≤ 20；名稱 ≤ 32 字元，僅限字母數字 `-` `_`，不分大小寫唯一 |
| 檔案 | 單一 events 檔 ≤ 4.2 GB；單模式事件 ≤ 10,000,000 筆；單局 JSON ≤ 1 MiB |
| 模擬 | 老師建議 10 萬–100 萬局；**不贏的結果不能占壓倒性多數**（例：10 萬局中 9 萬局 0 贏可被拒）；最常見單一結果不可過度主導 |
| **非關鍵測試**（失敗不擋提交，但會**降低最大下注額度**） | 標準差 ≤ 60；最大贏分 ≤ 100,000×；CVaR（每注）≤ 700；尾部機率 P(≥5,000×) ≤ 5%、P(≥10,000×) ≤ 1%、P(≥25,000×) ≤ 0.5%、P(≥50,000×) ≤ 0.1%、P(≥100,000×) ≤ 0.05%；另有 Expected Tail Liability 多項。分 6 類，失敗類別越多，額度上限越低 |
| 下注額度 | 基礎下注 $1–$1,000，依最大贏分、成本、波動度、風險自動指派模板；**降低最大贏分可得到較高下注額度**，且上線後不可改 |

### 4.3 前端（Front-end communication）
- **必須使用獨特的自製素材**；**web-sdk 範例的背景/符號/動畫一律不通過**
- 不能顯示 Stake Engine 載入器/Logo/啟動畫面；圖片與字型必須從 Engine CDN 載入（**不可用 Google Fonts / 外部 CDN / 分析工具**）
- 支援 Popout 小視窗（400×225、800×450）不變形；支援手機；筆電 1024×576；整頁不可捲動；手機禁用雙擊縮放
- 規則/資訊頁：玩法說明、每個模式成本與內容、**各模式 RTP**、**各模式最大贏分**、所有符號賠率、特殊符號所有可能值、免費遊戲觸發與再觸發規則、**操作說明（每個按鈕）**、**通用免責聲明**
- UI：可改下注額、可用 authenticate 回傳的**全部**下注級距、顯示餘額、顯示最終贏分、**多段贏分須逐步累加到最終金額**、可關閉聲音（全部音源）、**空白鍵 = 下注**、自動玩必須先確認（不可一鍵連續下注）、**成本 > 2× 的模式必須先確認**（顯示成本）
- 多幣別：USD、EUR、CAD、MXN、JPY(0 位小數)、USDT、BTC(6 位小數)；小於 0.01 的派彩要正確顯示
- 語言：`lang=en` 必須完整英文；未知語言碼回退英文
- **Replay（重播）**：`replay=true` 網址參數載入，不得呼叫錢包 API，必須顯示下注額與實際成本

### 4.4 Stake.us 社交模式（必過）
- 以 `social=true` 網址參數偵測（不是 jurisdiction 旗標）；**社交模式只支援英文**，且**不要做遊戲內語言切換器**
- 幣別顯示 `10.00 SC` / `10.00 GC`，不可有 `$`
- 所有玩家可見文字禁用 **bet / buy / pay / paytable / cash / money / deposit / wager / stake / purchase / bonus buy / win feature…**（完整替換表見 APPROVAL_CHECKLIST.md）。→ **模式名稱不能叫 Bonus Buy；"Paytable" 要改叫 "Symbol wins" 之類**；重播視窗也要合規
- 建議做一份 `sweeps_en` 語言檔

### 4.5 審核與評級
- 3 位評審各打 0–3 星（1/3 為單位），總分 /9，**≥ 6 分才能上架**；< 6 分該討論串鎖定 **3 天**
- **只有 3 星遊戲能進 New Releases / Slots / Burst Games**；3 星 = 全方位有工作室級品質。常見失分：基礎勝利動畫、靜態符號/背景/角色、平淡的下注 UI、資訊頁、購買選單、概念太簡單、**依賴通用 AI 素材（預設字型、漸層、emoji 圖示、邊框特效不夠）**、**只能玩 1–2 次就膩（缺乏深度）**、缺少紅利玩法、**載入太慢（要優化體積）**
- 評審**不給回饋**；重評冷卻 3 天；上線後評級鎖定
- **新團隊同時只能有 1 款遊戲在審核**，首款上線後最多 5 款
- 審核可快至數小時；不合規的提交會拖到數週
- 官方提供 **AI 自查提示 `prompt.md`**（含所有條目編號），建議每次提交前跑一次

### 4.6 排名與推廣
- New Releases 依「團隊 Engine Insights 排名（過去 30 天）」每週五（澳洲時間）排列 → **新團隊排名低，曝光要靠自己**
- 無付費置頂（另有 promoteonstake.com 付費推廣表單）；可自行經營 X、Stake 追蹤者、直播主分潤、Stake Challenges（需 Level 2 KYC + 至少一款上線遊戲）

## 5. 交付流程

1. 建團隊（Google/GitHub/Discord 登入）→ 設定 Provider 名稱（上線前可改，之後固定；避免 `& '` 與重音）→ 選付款模式 → 加錢包
2. 建遊戲、上傳 **數學檔**（index.json + CSV + .jsonl.zst）與 **靜態前端**（根目錄有 index.html，相對路徑）
3. 準備 **3:4 遊戲圖塊** 與 **16:9 封面圖**
4. 用 Studio 的 **Share** 連結讓測試者試玩（可隨時撤銷）；用 Social Mode 開關測試
5. 提交審核（附簡短玩法描述；選發行方式）→ 評級 → QA 檢查表 → 通過即自動上線（**不能排程上線日期**）

## 6. 工具鏈
Math SDK（Python ≥ 3.12 + Rust 優化器）／Web SDK（Svelte 5 + PixiJS 8 + Turborepo，Node 22.16、pnpm 10.5；**可不用，只要 build 出根目錄有 index.html 的靜態網站**）／RGS Client（`github.com/engineio/ts-client`）／Design system（`engineio.github.io/ui`）。官方 SDK repo 已搬到 `engineio` 組織。

## 7. 對專案的關鍵影響（PM 結論）
1. **品質是最大風險，不是數學。** 3 星才有曝光，且要原創美術、精緻動畫、完整 UI。美術與動畫工作量遠大於數學。
2. **可用 AI 生成素材**，但要精修與統一風格；通用預設字型/漸層不行。
3. 所有模式 RTP 落在 96.0–96.7% → 可讓 Bonus 模式有略不同 RTP，但不必要；我們統一 96.30%。
4. 標準差上限 60、尾部機率限制 → 波動度要「高但可控」，最大贏分 10,000× 在安全範圍內。
5. 社交模式字詞限制會影響所有 UI 命名，**一開始就要做雙語言檔架構**。
6. 新團隊同時只能 1 款在審核、失敗鎖 3 天 → **提交前務必自查，不要試錯**。
